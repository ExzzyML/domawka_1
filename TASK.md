# Домашняя работа №1. Линейные модели с нуля

## Цель

Реализовать с нуля небольшой набор линейных моделей с единым API:

* `BaseLinearModel` — абстрактный базовый класс;
* `LinearRegression` — линейная регрессия;
* `LogisticRegression` — логистическая регрессия.

Основная цель работы — спроектировать общую архитектуру линейных моделей и самостоятельно реализовать обучение, регуляризацию, предсказания и необходимые функции оптимизации.

Внутри реализации моделей нельзя использовать готовые модели и оптимизаторы из `sklearn`, `scipy.optimize` и аналогичных библиотек.

Для основной реализации достаточно `numpy` и стандартной библиотеки Python.

---

# 1. Структура классов

Необходимо реализовать три класса:

```python
BaseLinearModel
├── LinearRegression
└── LogisticRegression
```

Базовый класс должен содержать общую для линейных моделей функциональность.

Ориентировочная сигнатура:

```python
from abc import ABC, abstractmethod


class BaseLinearModel(ABC):

    def __init__(
        self,
        fit_intercept=True,
        solver="gradient",
        penalty=None,
        alpha=0.0,
        learning_rate=0.01,
        max_iter=1000,
        tol=1e-6,
        verbose=False,
        random_state=None,
    ):
        ...

    @abstractmethod
    def fit(self, X, y):
        ...

    @abstractmethod
    def predict(self, X):
        ...

    @abstractmethod
    def _loss(self, X, y):
        ...

    @abstractmethod
    def _gradient(self, X, y):
        ...
```

Дополнительные внутренние методы можно проектировать самостоятельно.

Необходимо постараться вынести общую логику в `BaseLinearModel` и минимизировать дублирование между дочерними классами.

---

# 2. Общие требования к моделям

После вызова `fit` обе модели должны иметь атрибуты:

```python
coef_
intercept_
n_iter_
loss_history_
```

Модели должны поддерживать параметр:

```python
fit_intercept
```

Свободный член не должен участвовать в регуляризации.

Метод `fit` должен возвращать `self`.

Пример:

```python
model = LinearRegression(...)
model.fit(X, y)

predictions = model.predict(X)

print(model.coef_)
print(model.intercept_)
print(model.n_iter_)
print(model.loss_history_)
```

---

# 3. LinearRegression

Реализовать:

```python
class LinearRegression(BaseLinearModel):
    ...
```

Модель должна поддерживать два способа обучения:

```python
solver="analytic"
solver="gradient"
```

## Аналитическое обучение

Для `solver="analytic"` необходимо реализовать аналитическое решение задачи линейной регрессии.

Должны поддерживаться:

```python
penalty=None
penalty="l2"
```

Комбинации параметров, для которых аналитического решения в рамках этой домашней работы не предусмотрено, должны приводить к понятной ошибке.

Реализация должна корректно обрабатывать вырожденные или плохо обусловленные данные.

## Gradient solver

Для `solver="gradient"` необходимо реализовать обучение с помощью градиентной оптимизации.

Должны поддерживаться:

```python
penalty=None
penalty="l1"
penalty="l2"
```

В качестве функции потерь используется стандартная функция потерь линейной регрессии.

Функция потерь и её градиент должны быть реализованы самостоятельно.

# 4. LogisticRegression

Реализовать:

```python
class LogisticRegression(BaseLinearModel):
    ...
```

В рамках этой домашней работы логистическая регрессия должна поддерживать:

```python
solver="gradient"
```

Попытка использовать неподдерживаемый solver должна приводить к понятной ошибке.

Модель должна решать задачу бинарной классификации.

Допустимые значения целевой переменной:

```python
0
1
```

Должны быть реализованы:

```python
fit(X, y)
predict(X)
predict_proba(X)
```

`predict_proba` должен возвращать массив формы:

```python
(n_samples, 2)
```

Например:

```python
proba[:, 0]  # вероятность класса 0
proba[:, 1]  # вероятность класса 1
```

Для преобразования вероятностей в классы должен использоваться threshold.

По умолчанию:

```python
threshold = 0.5
```

Можно добавить его как параметр модели.

Необходимо самостоятельно реализовать:

* преобразование линейного выхода модели в вероятность;
* функцию потерь;
* градиент функции потерь.

Реализация должна корректно работать на значениях, на которых наивные вычисления могут приводить к численным проблемам.

---

# 5. Gradient solver

Общую логику градиентного обучения желательно реализовать на уровне `BaseLinearModel`.

Solver должен использовать параметры:

```python
learning_rate
max_iter
tol
```

Во время обучения необходимо сохранять историю функции потерь:

```python
loss_history_
```

и фактическое количество выполненных итераций:

```python
n_iter_
```

---

# 6. Early stopping

Gradient solver должен поддерживать досрочную остановку.

Критерий остановки необходимо выбрать и реализовать самостоятельно.

Он должен использовать параметр:

```python
tol
```

Выбранный критерий необходимо кратко описать в `README.md`.

После срабатывания early stopping:

```python
n_iter_ < max_iter
```

---

# 7. Регуляризация

Необходимо поддержать:

```python
penalty=None
penalty="l1"
penalty="l2"
```

Сила регуляризации задаётся параметром:

```python
alpha
```

Требования:

* `LinearRegression(solver="gradient")` поддерживает `None`, `l1`, `l2`;
* `LinearRegression(solver="analytic")` поддерживает `None`, `l2`;
* `LogisticRegression(solver="gradient")` поддерживает `None`, `l1`, `l2`;
* intercept не регуляризуется.

Неподдерживаемые комбинации параметров должны приводить к понятным исключениям.

### Дополнительное задание

Добавить:

```python
penalty="elasticnet"
```

и соответствующий дополнительный параметр.

# 8. Валидация данных и параметров

Модели должны проверять входные данные.

Минимально необходимо проверять:

```python
X.ndim == 2
y.ndim == 1
len(X) == len(y)
```

Также необходимо валидировать параметры модели:

```python
learning_rate
max_iter
tol
alpha
solver
penalty
```

`LogisticRegression` должна отдельно проверять корректность целевой переменной.

При некорректных данных или параметрах модель должна выбрасывать понятные исключения.

Тип исключений и тексты сообщений можно выбрать самостоятельно.

# 9. API

Следующий интерфейс должен работать:

```python
model = LinearRegression(
    solver="gradient",
    penalty="l2",
    alpha=0.1,
    learning_rate=0.01,
    max_iter=5000,
    tol=1e-7,
)

model.fit(X_train, y_train)

pred = model.predict(X_test)

print(model.coef_)
print(model.intercept_)
print(model.n_iter_)
print(model.loss_history_)
```

Для классификации:

```python
model = LogisticRegression(
    penalty="l2",
    alpha=0.01,
    learning_rate=0.1,
    max_iter=5000,
)

model.fit(X_train, y_train)

pred = model.predict(X_test)
proba = model.predict_proba(X_test)
```

# 10. Требования к архитектуре

Нельзя реализовывать всю логику внутри одного большого метода `fit`.

Код необходимо разделить на логические части.

Названия и количество внутренних методов можно выбрать самостоятельно.

Важно, чтобы:

* общий код не дублировался между моделями;
* специфичная для конкретной модели логика находилась в дочернем классе;
* общая логика обучения по возможности находилась в базовом классе;
* публичный API моделей был одинаковым там, где это имеет смысл;
* классы не зависели от кода из ноутбука или тестов.
