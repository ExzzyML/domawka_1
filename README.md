# Линейные модели с нуля

Линейная и логистическая регрессии на `numpy` с собственным градиентным спуском и аналитическим решением. Внутри пакета `linear_models` библиотека `scikit-learn` не используется; она нужна только ноутбуку `experiments.ipynb`, где свои модели сравниваются с `sklearn`.

Проверено на Python 3.12.7, `numpy` 2.5.3, `scikit-learn` 1.9.1.

## Установка и быстрый старт

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows; на Linux и macOS: source .venv/bin/activate
pip install -r requirements.txt
```

`linear_models/__init__.py` пустой, поэтому классы импортируются из своих модулей:

```python
import numpy as np
from linear_models.linear_regression import LinearRegression
from linear_models.logistic_regression import LogisticRegression

# Регрессия: точная прямая y = 2x + 1, аналитическое решение
X = np.array([[0.0], [1.0], [2.0], [3.0]])
y = 2 * X[:, 0] + 1
model = LinearRegression(solver="analytic").fit(X, y)
print(model.coef_, model.intercept_)          # [2.] 1.0

# Та же задача градиентным спуском с L2-штрафом (веса «сжимаются»)
model = LinearRegression(
    solver="gradient", penalty="l2", alpha=0.1,
    learning_rate=0.1, max_iter=5000, tol=1e-9,
).fit(X, y)
print(model.coef_.round(3), round(model.intercept_, 3), model.n_iter_)   # [1.852] 1.222 219

# Классификация
X = np.array([[-3.0], [-1.0], [1.0], [2.0]])
y = np.array([0, 0, 1, 1])
clf = LogisticRegression(penalty="l2", alpha=0.01, learning_rate=0.5, max_iter=5000, tol=1e-9).fit(X, y)
print(clf.predict(X))                         # [0 0 1 1]
print(clf.predict_proba(X).round(3))          # столбцы: P(класс 0), P(класс 1)
```

## Архитектура

```text
BaseLinearModel (абстрактный)
├── LinearRegression
└── LogisticRegression
```

- `BaseLinearModel` (`linear_models/base.py`) хранит параметры, проверяет их и входные данные, содержит градиентный и проксимальный спуск `_fit_gradient`, общий цикл итераций `_run_iterations` (история, callbacks, `verbose`, `tol`, предупреждения), штраф и его градиент, ранний останов, `coef_`, `intercept_`, `n_iter_`, `loss_history_`. Подклассы реализуют `fit`, `predict`, `_loss` и `_gradient`.
- `X` и `y` должны состоять из конечных чисел: `NaN`, `±inf` и нечисловые значения дают понятный `ValueError` в `fit`, `predict` и `score`.
- `LinearRegression` (`linear_models/linear_regression.py`): потери `1/(2n) · Σ(z − y)²`; два solver'а.
- `LogisticRegression` (`linear_models/logistic_regression.py`): потери `mean(log(1 + e^z) − y·z)`, посчитанные через `np.logaddexp`; устойчивая сигмоида; есть `predict_proba` и порог `threshold`; свой solver `"newton"`.
- `NotFittedError` (наследник `ValueError`) бросается, если вызвать `predict` до `fit`.

### Параметры конструктора

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `fit_intercept` | `True` | обучать свободный член; при `False` `intercept_ = 0.0` |
| `solver` | `"gradient"` | `"gradient"`, `"proximal"`, `"analytic"` (только `LinearRegression`) или `"newton"` (только `LogisticRegression`) |
| `penalty` | `None` | `None`, `"l1"`, `"l2"` или `"elasticnet"` |
| `alpha` | `0.0` | сила штрафа, число `>= 0` |
| `l1_ratio` | `0.5` | доля L1 в штрафе `"elasticnet"`, число из `[0, 1]`; при других `penalty` не используется |
| `momentum` | `0.0` | коэффициент скорости `β`, число из `[0, 1)`; `0.0` даёт обычный спуск |
| `nesterov` | `False` | `True` включает момент Нестерова; требует `momentum > 0` |
| `lr_schedule` | `None` | `None` (постоянный шаг), `"exponential"`, `"inverse_time"` или `"step"` |
| `lr_decay` | `0.9` | параметр убывания шага, число `> 0` (для `"exponential"` и `"step"` не больше `1`) |
| `lr_step_size` | `10` | для `"step"`: через сколько итераций шаг умножается на `lr_decay`, целое `>= 1` |
| `store_gradients` | `False` | `True` сохраняет `gradient_history_` (только `solver="gradient"`) |
| `callbacks` | `None` | список функций `cb(model, iteration, loss)`, вызываются после каждой итерации |
| `batch_size` | `None` | `None`: градиент по всем объектам; целое `>= 1`: размер батча (`1` это SGD); только `solver="gradient"` |
| `shuffle` | `True` | перемешивать объекты в начале каждой эпохи (учитывается только при `batch_size`) |
| `learning_rate` | `0.01` | шаг градиентного спуска, число `> 0` |
| `max_iter` | `1000` | максимум итераций, целое `>= 1` |
| `tol` | `1e-6` | порог раннего останова, число `>= 0` |
| `verbose` | `False` | `True` печатает прогресс обучения (см. «Наблюдение за обучением») |
| `random_state` | `None` | `None` или целое `>= 0`; задаёт перемешивание объектов при `batch_size`, иначе не используется |
| `threshold` | `0.5` | только `LogisticRegression`: класс 1, если `P(1) > threshold` |

### Атрибуты после `fit`

| Атрибут | Что это |
|---|---|
| `coef_` | веса, массив формы `(n_features,)` (у многоклассовой логистической регрессии `(K, n_features)`) |
| `intercept_` | свободный член (число; у многоклассовой модели массив `(K,)`) |
| `n_iter_` | число выполненных итераций (при batch_size это эпохи) (у `analytic` равно 1) |
| `loss_history_` | список значений полной цели `J` после каждой итерации |
| `gradient_history_` | только при `store_gradients=True`: массив `(число шагов, d + 1)`, строка `i` содержит градиент цели (с учётом штрафа) перед шагом `i`, последний столбец интерцепт (при `fit_intercept=False` нули). При полном батче шагов столько же, сколько итераций |

`predict(X)` у регрессии возвращает значения `z = X @ coef_ + intercept_`; у классификации возвращает классы (`0` и `1` в бинарном случае, иначе исходные метки), `predict_proba(X)` возвращает массив формы `(n, 2)` или `(n, K)`. Подробности про несколько классов в разделе «Несколько классов (softmax)».

`score(X, y)` возвращает одно число: у регрессии коэффициент детерминации R² = 1 − Σ(y − z)² / Σ(y − ȳ)² (1 — идеал, 0 — не лучше среднего, может быть отрицательным), у классификации долю верных ответов (accuracy). Если `y` константа, R² не определён, и, как в `sklearn`, возвращается 1.0 при нулевой ошибке и 0.0 иначе.

## Solver'ы

| Solver | Где | Что делает |
|---|---|---|
| `"analytic"` | `LinearRegression`, `penalty` только `None` или `"l2"` | центрирует данные (если `fit_intercept=True`) и решает задачу наименьших квадратов через `np.linalg.lstsq`; L2 добавляет строки `√(n·alpha)·I` |
| `"gradient"` | обе модели, любой `penalty` | градиентный спуск (по умолчанию с постоянным шагом `learning_rate`, см. «Momentum и расписание шага»), с полным батчем или mini-batch; L1 через субградиент |
| `"proximal"` | обе модели, любой `penalty` | проксимальный градиентный спуск: шаг по гладкой части цели, затем мягкий порог; при L1 и `"elasticnet"` даёт точные нули; без `momentum` |
| `"newton"` | `LogisticRegression`, `penalty` только `None` или `"l2"` | метод Ньютона с дроблением шага: обычно 5–10 итераций до точности float |

У логистической регрессии нет замкнутой формы, поэтому `"analytic"` у неё нет; у линейной `"newton"` не нужен: для квадратичной цели один шаг Ньютона и есть точное решение, его даёт `"analytic"`.

### Проксимальный спуск (`solver="proximal"`)

Цель с L1 состоит из гладкой части `f(w) = потери + L2-часть штрафа` и негладкой `λ · Σ|w_j|`, где `λ = alpha` для `"l1"` и `λ = alpha · l1_ratio` для `"elasticnet"`. У `|w|` в нуле нет производной, поэтому субградиент `sign(w)` в `"gradient"` каждый раз толкает вес через ноль: вес колеблется около нуля с размахом порядка `learning_rate · λ` и точным нулём не становится.

Проксимальный шаг делит работу на две части:

1. обычный шаг по гладкой части: `u = w − lr · ∇f(w)`;
2. мягкий порог: `w = S(u, lr · λ)`, где `S(u, t) = sign(u) · max(|u| − t, 0)`.

`S` прижимает к нулю все значения из `[−t, t]` и сдвигает остальные на `t` к нулю: `S(0.3, 0.1) = 0.2`, `S(−0.05, 0.1) = 0`, `S(−0.4, 0.1) = −0.3`. Это точное решение задачи «найти `w`, близкий к `u`, с учётом штрафа `t·|w|`», поэтому ноль получается не случайно, а как оптимум.

Трасса на квадратичной цели из тестов (`∇f = w`, `lr = 0.5`, `alpha = 1`, порог `t = 0.5`), старт `w = (4, −2)`:

| шаг | `u = w − 0.5·w` | `proximal`: `S(u, 0.5)` | `gradient`: `w − 0.5·(w + sign(w))` |
|---|---|---|---|
| 1 | `(2, −1)` | `(1.5, −0.5)` | `(1.5, −0.5)` |
| 2 | `(0.75, −0.25)` | `(0.25, 0)` | `(0.25, 0.25)` |
| 3 | `(0.125, 0)` | `(0, 0)` | `(−0.375, −0.375)` |

На данных из тестов `LinearRegression(solver="proximal", penalty="l1")` совпадает с `sklearn.linear_model.Lasso` до `1e-15`, а `"elasticnet"` с `ElasticNet`, с нулями ровно на тех же местах; `LogisticRegression(solver="proximal", penalty="l1")` совпадает с sklearn `saga`. При `penalty=None` или `"l2"` порог равен нулю, и `"proximal"` даёт ровно то же, что `"gradient"`. Mini-batch и расписание шага работают; `momentum > 0` даёт `ValueError`: для «тяжёлого шара» вместе с порогом нет гарантии сходимости (у ускоренного проксимального метода FISTA своя формула). В `gradient_history_` попадает градиент гладкой части.

### Метод Ньютона (`solver="newton"`)

Градиентный спуск знает только наклон цели. Метод Ньютона приближает цель в текущей точке параболой (рядом Тейлора до второго порядка) и прыгает сразу в её минимум: `θ ← θ − H⁻¹g`, где `θ = (w, b)`, `g` градиент, `H` матрица вторых производных (гессиан). Для логистической регрессии:

- `g = Xaᵀ(p − y) / n + alpha · (w, 0)`;
- `H = Xaᵀ diag(p(1 − p)) Xa / n + alpha · diag(1, …, 1, 0)`;

где `Xa = [X, 1]` (столбец единиц только при `fit_intercept=True`), `p = σ(z)`. С весами объектов `(p − y)` и `p(1 − p)` умножаются на `wᵢ`, а `n` заменяется на `Σw`. `p(1 − p) > 0`, поэтому `H` положительно полуопределена и парабола «смотрит вверх». Систему `H·d = g` решает `np.linalg.lstsq`: на вырожденной `H` (например, повторяющиеся признаки) это не падает.

Трасса первого шага на `X = (0, 1, 2, 3)`, `y = (0, 1, 0, 1)`, старт `θ = 0`:

1. `p = 0.5` у всех объектов, `p − y = (0.5, −0.5, 0.5, −0.5)`, `p(1 − p) = 0.25`.
2. `g = (mean(x·(p − y)), mean(p − y)) = ((0 − 0.5 + 1 − 1.5)/4, 0) = (−0.25, 0)`.
3. `H = 0.25 · [[mean(x²), mean(x)], [mean(x), 1]] = 0.25 · [[3.5, 1.5], [1.5, 1]] = [[0.875, 0.375], [0.375, 0.25]]`.
4. `det H = 0.875·0.25 − 0.375² = 0.078125`, `H⁻¹ = [[0.25, −0.375], [−0.375, 0.875]] / 0.078125 = [[3.2, −4.8], [−4.8, 11.2]]`.
5. `d = H⁻¹g = (3.2·(−0.25), −4.8·(−0.25)) = (−0.8, 1.2)`, новый `θ = 0 − d = (0.8, −1.2)`; цель падает с `log 2 = 0.6931` до `0.5881`.

Решение `(0.9082, −1.3623)` достигается за 4 итерации (`tol` по умолчанию).

**Квадратичная сходимость.** Рядом с минимумом ошибка на каждом шаге примерно возводится в квадрат. На 60 объектах из тестов расстояние до минимума по цели: `3.7·10⁻²`, `4.1·10⁻³`, `8.6·10⁻⁵`, `4.9·10⁻⁸`, `1.6·10⁻¹⁴`. Итог: 6 итераций против 633 у градиентного спуска с `learning_rate=0.5` при том же `tol=1e-12`; коэффициенты совпадают с sklearn до `1e-8` (без штрафа точность ограничена самим `lbfgs` sklearn, с L2 совпадение до `1e-12`).

**Дробление шага.** Вдали от решения полный шаг Ньютона может увеличить цель. Поэтому шаг делается как `θ − t·d`, где `t = 1, 1/2, 1/4, …`, и берётся первое `t` с условием Армихо `J(θ − t·d) ≤ J(θ) − 10⁻⁴ · t · (g·d)`. Если такого `t` нет (уже в минимуме с точностью float), параметры не меняются, и следующая итерация останавливается по `tol`. На логистической цели со стартом из нуля полный шаг на практике почти всегда принимается (на 20 000 случайных наборах ни разу не понадобилось дробление), так что это страховка; тест проверяет её на направлении `8·d`: `t = 1` и `t = 1/2` увеличивают цель, `t = 1/4` принимается.

`"newton"` использует все объекты в каждом шаге, поэтому `batch_size` с ним даёт `ValueError`; L1 и `"elasticnet"` тоже дают `ValueError` (у `|w|` нет второй производной). `learning_rate`, `momentum`, `nesterov` и расписание шага не используются. `n_iter_`, `loss_history_`, `tol`, callbacks, `verbose`, `store_gradients` и предупреждения работают как у спуска. Цена итерации `O(n·d² + d³)` против `O(n·d)` у градиента: при тысячах признаков каждая итерация дорогая.

## Несколько классов (softmax)

`LogisticRegression` сама определяет задачу по `y`. Метки `{0, 1}` дают бинарную модель как раньше. Любые другие целые метки (например, `[3, 5, 7]` или `[0, 1, 2]`) дают многоклассовую модель; нужно минимум два разных класса, нецелые значения дают `ValueError`. Параметров для переключения нет, а при повторном `fit` форма модели определяется заново.

**Идея.** Для каждого класса `k` своя линейная оценка `zₖ = wₖ·x + bₖ`. Softmax превращает `K` оценок в вероятности, которые положительны и в сумме дают 1: `pₖ = exp(zₖ) / Σₗ exp(zₗ)`. Цель (кросс-энтропия) для объекта с классом `c` равна `−log p_c = logsumexp(z) − z_c`; полная цель это среднее по объектам плюс штраф. Для устойчивости из всех `z` перед `exp` вычитается максимум строки, результат тот же, но `exp` не переполняется.

**Градиент.** Пусть `P` матрица вероятностей `(n, K)`, `Y` one-hot матрица верных классов. Тогда `∇W = (P − Y)ᵀ X / n` (форма `(K, d)`), `∇b = Σ(P − Y) / n` (форма `(K,)`). С `sample_weight` каждая строка умножается на `wᵢ`, а `n` заменяется на `Σw`. L2 добавляет `alpha · W` (интерцепт не штрафуется).

**Трасса на числах.** Один признак `X = (0, 1, 2)`, классы `y = (0, 1, 2)`, старт `W = 0`, `b = 0`:

1. Все `z = 0`, поэтому `P = 1/3` в каждой клетке; цель `log 3 = 1.0986`.
2. `∇W[k] = mean((P[:,k] − Y[:,k]) · x)`: класс 0: `(1/3·0 + 1/3·1 + 1/3·2)/3 = 1/3`; класс 1: `(1/3·0 − 2/3·1 + 1/3·2)/3 = 0`; класс 2: `(1/3·0 + 1/3·1 − 2/3·2)/3 = −1/3`. Градиент интерцептов нулевой (`Σ(P − Y) = 0` у каждого класса).
3. Шаг `learning_rate = 0.5`: `W = −0.5 · (1/3, 0, −1/3) = (−1/6, 0, 1/6)`; цель падает с `1.0986` до `1.0028`.

Строки градиента в сумме по классам дают 0 (`Σₖ (pₖ − yₖ) = 0`), поэтому старт из нуля сохраняет `Σₖ Wₖ = 0` на всех шагах: вероятности не меняются, если ко всем `zₖ` прибавить одно число, и градиентный спуск движется только по «осмысленным» направлениям.

**Формы и атрибуты.**

| Что | Бинарная | `K` классов |
|---|---|---|
| `coef_` | `(d,)` | `(K, d)`, строка `k` относится к `classes_[k]` |
| `intercept_` | число | `(K,)` |
| `classes_` | `[0, 1]` | отсортированные уникальные метки |
| `predict_proba(X)` | `(n, 2)` | `(n, K)`, столбцы в порядке `classes_`, строки в сумме дают 1 |
| `predict(X)` | `0`/`1` по порогу | `classes_[argmax]`, исходные метки |
| `gradient_history_` | `(шагов, d + 1)` | `(шагов, K · (d + 1))`, строки `(wₖ, bₖ)` подряд для `k = 0..K−1` |

`threshold` в многоклассовой модели не используется (выбирается самый вероятный класс). Каждый класс должен иметь положительный суммарный `sample_weight`, иначе `ValueError`.

**Solver'ы.** Работают `gradient` (с momentum, Nesterov, расписанием, mini-batch), `proximal` (L1 и `elasticnet` с точными нулями; на тестах совпадает с sklearn `saga`, 9 нулей из 9 на тех же местах) и `newton`. У Ньютона вместо матрицы `(d+1)×(d+1)` блочный гессиан `K(d+1)×K(d+1)`, блок `(k, l)` равен `Xaᵀ diag(s · (δₖₗ pₖ − pₖ pₗ)) Xa / Σs` (`s` веса объектов, `δₖₗ` единица при `k = l`). Он вырожден (сдвиг всех `W` на одно значение цель не меняет), поэтому система решается через `lstsq`, как и раньше.

**Связь с бинарной моделью.** Два класса с метками не `{0, 1}` (например, `{1, 2}`) тоже идут через softmax. При `K = 2` он эквивалентен сигмоиде, но разность оценок равна `z₁ − z₀`, а не `z`, поэтому градиентный спуск с `learning_rate = lr` в softmax-режиме даёт ту же вероятность, что бинарная модель с `2·lr` (проверено тестом), а Ньютон даёт те же вероятности до `1e-8`.

**Сверка с sklearn.** На 60 объектах из тестов (3 класса, `alpha = 0.1`, `C = 1 / (n · alpha)`): Ньютон за 6 итераций совпадает до `5·10⁻⁸`, градиентный спуск (`learning_rate=0.5`, 362 итерации) до `2·10⁻⁶`; предсказанные классы совпадают на 100 %. Коэффициенты: `[[−0.5013, −0.5382], [0.9421, −0.3297], [−0.4408, 0.8679]]`, интерцепты `[1.1686, −0.5699, −0.5987]`.

## Регуляризация

Цель, которую минимизируют обе модели: `J(w, b) = потери(w, b) + alpha · R(w)`, где потери усреднены по объектам.

| `penalty` | `R(w)` | Градиент штрафа |
|---|---|---|
| `None` | 0 | нет |
| `"l2"` | `½ · ‖w‖²` | `alpha · w` |
| `"l1"` | `Σ\|w_j\|` | `alpha · sign(w)` (субградиент) |
| `"elasticnet"` | `l1_ratio · Σ\|w_j\| + ½ · (1 − l1_ratio) · ‖w‖²` | `alpha · (l1_ratio · sign(w) + (1 − l1_ratio) · w)` |

Свободный член `intercept_` не штрафуется ни в одном режиме.

`l1_ratio=0` даёт ровно L2, `l1_ratio=1` ровно L1. `"elasticnet"` работает с `solver="gradient"` и `"proximal"`. С `"gradient"` L1-часть идёт через субградиент: коэффициенты малы, но без точных нулей. Точные нули даёт `solver="proximal"` (см. «Solver'ы»).

## Momentum и расписание шага

Оба механизма работают в `solver="gradient"` (расписание шага также в `"proximal"`) и по умолчанию выключены (`momentum=0.0`, `lr_schedule=None`): тогда спуск ровно прежний.

**Momentum.** На каждой итерации накапливается скорость `v = momentum · v + g`, где `g` градиент цели (потери плюс штраф), и веса обновляются как `w = w − lr_t · v`. Интерцепт получает свою скорость. Скорость обнуляется в начале каждого `fit`. Если шаг велик, момент может «перелететь» минимум: цель на короткое время вырастет, а потом снова упадёт.

**Момент Нестерова** (`nesterov=True`). Скорость копится так же, `v = momentum · v + g`, но шаг делается по направлению `g + momentum · v`: `w = w − lr_t · (g + momentum · v)`. Это запись из PyTorch, она эквивалентна классической форме «градиент в точке взгляда вперёд» `u = β·u − lr·∇J(w + β·u)`, `w = w + u`: веса модели совпадают с точкой `w + β·u` (это проверяет тест). Смысл: обычный момент сначала разгоняется, а потом смотрит на градиент; Нестеров учитывает, куда скорость унесёт веса, и раньше начинает тормозить. На квадратичной цели из тестов обычный момент с `β = 0.5`, `lr = 0.5` проходит `4 → 2 → 0 → −1`, а Нестеров `4 → 1 → −0.25 → −0.4375`: перелёт за минимум меньше. На плохо обусловленной регрессии из тестов (`lr = 0.5`, `β = 0.9`, 200 итераций) цель растёт на 36 итерациях вместо 84. Цена: диапазон устойчивых шагов у Нестерова уже. Для квадратичной цели с кривизной `L` обычный момент сходится при `lr · L < 2(1 + β)`, а Нестеров при `lr · L < 2(1 + β)/(1 + 2β)`; при `β = 0.9` это `3.8` против `1.36`. У той регрессии `L ≈ 1`, и при `learning_rate=1.5` обычный момент сходится, а Нестеров расходится (тоже проверено тестом). Поэтому слишком большой `learning_rate` с `nesterov=True` раньше приводит к расходимости. При `momentum = 0` Нестеров совпал бы с обычным спуском, поэтому `nesterov=True` без момента даёт `ValueError`.

**Расписание шага.** `lr_t` зависит от номера итерации `t = 0, 1, 2, …`:

| `lr_schedule` | `lr_t` |
|---|---|
| `None` | `learning_rate` |
| `"exponential"` | `learning_rate · lr_decay^t` |
| `"inverse_time"` | `learning_rate / (1 + lr_decay · t)` |
| `"step"` | `learning_rate · lr_decay^⌊t / lr_step_size⌋` |

`"step"` держит шаг постоянным `lr_step_size` итераций, затем умножает его на `lr_decay`: при `learning_rate=0.5`, `lr_decay=0.5`, `lr_step_size=2` шаги равны `0.5, 0.5, 0.25, 0.25, 0.125, …`. При `lr_step_size=1` это ровно `"exponential"`. `lr_step_size` проверяется всегда, но используется только с `"step"`.

Правило останова из следующего раздела остаётся прежним. Но если шаг убывает, изменения цели тоже сжимаются, и останов по `tol` срабатывает раньше. Для проверки сходимости с расписанием лучше брать `tol=0.0` или маленький `tol`.

## Наблюдение за обучением

**История градиентов.** При `store_gradients=True` в `gradient_history_` попадает градиент, по которому сделан каждый шаг: градиент потерь плюс градиент штрафа в точке до обновления (не скорость momentum). Нормы получаются так: `np.linalg.norm(model.gradient_history_, axis=1)`. У `solver="analytic"` итераций нет, поэтому `store_gradients=True` с ним даёт `ValueError`. Если после такого обучения запустить `fit` без истории, старый `gradient_history_` удаляется.

**Callbacks.** Каждая функция из `callbacks` вызывается как `cb(model, iteration, loss)` после каждого обновления весов: `iteration` считается с единицы (как `n_iter_`), `loss` значение полной цели `J` на этой итерации. Если функция вернёт bool `True`, обучение остановится после этой итерации; любой другой результат игнорируется. Вызываются все функции списка, даже если первая уже попросила остановку. Callbacks и `verbose` игнорируются у `solver="analytic"`.

```python
def stop_when_small(model, iteration, loss):
    return loss < 0.01

model = LinearRegression(callbacks=[stop_when_small]).fit(X, y)
```

**`verbose=True`.** Печатается строка `iter 1: J=...`, затем каждые 100 итераций, и в конце итог: `stopped at iteration k: J=..., reason: max_iter | tol | callback | diverged.

## Веса объектов (`sample_weight`)

`fit(X, y, sample_weight=w)` принимает веса объектов `w` формы `(n,)`: неотрицательные конечные числа с положительной суммой, иначе `ValueError`. Вес `k` равносилен `k` копиям объекта, вес `0` равносилен удалению объекта. По умолчанию `sample_weight=None`: все веса равны 1, результат ровно прежний.

Все «средние по объектам» становятся взвешенными, то есть делятся на `Σw`, а не на `n`:

| Что | Формула |
|---|---|
| потери линейной регрессии | `Σ wᵢ·rᵢ² / (2·Σw)` |
| потери логистической регрессии | `Σ wᵢ·ℓᵢ / Σw` |
| градиент по `w`, `b` | `Xᵀ(w·r) / Σw`, `Σ(w·r) / Σw` |

Поэтому умножение всех весов на одно число ничего не меняет, а `Σw` играет роль «эффективного `n`». `solver="analytic"` тоже поддерживает веса: данные центрируются по взвешенным средним, строки `X` и `y` умножаются на `√wᵢ`, для L2 добавляются строки `√(Σw·alpha)·I`. У `LogisticRegression` оба класса должны присутствовать среди объектов с положительным весом. Веса принимает и `score`.

## Mini-batch и SGD

При `batch_size=None` (по умолчанию) каждый шаг использует градиент по всем объектам. При целом `batch_size` данные в каждой эпохе режутся на батчи, и на каждый батч делается один шаг: `batch_size=1` даёт SGD, `batch_size=n` равносилен полному батчу. Последний батч может быть меньше остальных.

Итерация при батчах это **эпоха**, один проход по данным. Поэтому `max_iter` считает эпохи, `n_iter_` и `loss_history_` пополняются раз в эпоху (в `loss_history_` попадает полная цель `J` по всем данным в конце эпохи), расписание шага зависит от номера эпохи, а callbacks и `verbose` срабатывают раз в эпоху. Momentum обновляется на каждом шаге; штраф входит в градиент каждого шага целиком. С весами в батче берётся взвешенное среднее по батчу; батч с нулевой суммой весов пропускается.

При `shuffle=True` порядок объектов перемешивается заново в каждой эпохе генератором `np.random.default_rng(random_state)`, созданным один раз в начале `fit`: одинаковый `random_state` даёт одинаковый результат. `shuffle=False` оставляет исходный порядок. Если `batch_size` не меньше числа объектов, это полный батч: данные не копируются и не перемешиваются, результат совпадает с `batch_size=None`. `solver="proximal"` поддерживает батчи так же (порог применяется после каждого шага). `solver="analytic"` шагов не делает, а `"newton"` каждый шаг считает по всем объектам, поэтому `batch_size` с ними даёт `ValueError`.

Шаги по батчам «шумные»: цель `J` может колебаться от эпохи к эпохе, а правило останова по `tol` сравнивает соседние эпохи и может сработать случайно. При SGD стоит брать небольшой `tol` или `tol=0.0`.

## Early stopping

После каждого обновления весов считается полная цель `J` (потери плюс штраф) и дописывается в `loss_history_`. Спуск останавливается, как только `|J_{k-1} − J_k| < tol`. Поэтому:

- `n_iter_ == len(loss_history_)`;
- `tol = 0.0` отключает остановку: выполнится ровно `max_iter` итераций;
- правило смотрит на изменение цели, а не на расстояние до решения: на плохо обусловленных данных оно срабатывает рано (см. раздел 5.3 ноутбука).

## Предупреждения

Итерационные solver'ы (`"gradient"`, `"proximal"`, `"newton"`) выдают `ConvergenceWarning` (наследник `UserWarning`, импорт из `linear_models.base`) в двух случаях:

- **не сошёлся**: выполнено `max_iter` итераций, а изменение цели так и не стало меньше `tol`. При `tol = 0.0` предупреждения нет: останов отключён сознательно;
- **разошёлся**: цель `J` стала `inf` или `nan` (обычно из-за слишком большого `learning_rate`). Обучение сразу останавливается, `n_iter_` равен номеру этой итерации, последнее значение `loss_history_` равно `inf` или `nan`. Предупреждения numpy о переполнении на время спуска отключены, остаётся одно понятное сообщение.

Аналитический solver предупреждений не выдаёт. Скрыть предупреждение можно стандартно:

```python
import warnings
from linear_models.base import ConvergenceWarning

with warnings.catch_warnings():
    warnings.simplefilter("ignore", ConvergenceWarning)
    model.fit(X, y)
```

## Соответствие параметрам `sklearn`

Наша цель делится на `n`, поэтому `alpha` нужно пересчитывать (здесь `n` — число обучающих объектов):

| Наша модель | Модель sklearn | Соответствие |
|---|---|---|
| `LinearRegression`, `penalty="l2"`, `alpha` | `Ridge` | `alpha_sklearn = n · alpha` |
| `LinearRegression`, `penalty="l1"`, `alpha` | `Lasso` | `alpha_sklearn = alpha` |
| `LinearRegression`, `penalty="elasticnet"`, `alpha`, `l1_ratio` | `ElasticNet` | `alpha_sklearn = alpha`, `l1_ratio` тот же |
| `LogisticRegression`, `penalty="l2"`, `alpha` | `LogisticRegression(l1_ratio=0, C=C)` | `C = 1 / (n · alpha)` |
| `LogisticRegression`, `penalty="l1"`, `alpha` | `LogisticRegression(l1_ratio=1, solver="saga", C=C)` | `C = 1 / (n · alpha)` |
| без штрафа | `LogisticRegression(C=np.inf)` | параметр `penalty` в sklearn 1.9 устарел |

С `sample_weight` в формулах пересчёта `alpha` вместо `n` стоит `Σw`: `Ridge(alpha = Σw · alpha)`, `LogisticRegression(C = 1 / (Σw · alpha))` (проверено числами, совпадение до `1e-10`).

## Что показал ноутбук

Те же данные (`train_test_split`, `random_state=42`, стандартизация по обучающей части) подавались и в свои модели, и в `sklearn`:

- линейная регрессия (analytic и gradient, без штрафа и с L2): коэффициенты совпадают с `sklearn` до `6.4e-13`;
- логистическая регрессия (без штрафа и с L2): коэффициенты до `2.6e-7`, классы на тесте совпадают на 100 % (кроме разделимого случая ниже); разность задаётся точностью самого `lbfgs` в sklearn, а не нашей;
- L1 субградиентом (`solver="gradient"`): значение цели совпадает с `sklearn`, но точных нулей нет (колебания порядка `learning_rate · alpha`), у `saga` они есть; `solver="proximal"` появился позже и даёт те же нули, что sklearn (см. «Solver'ы»);
- на линейно разделимых данных без штрафа (`breast_cancer`) веса растут вместе с числом итераций, поэтому сравниваются предсказания, а не коэффициенты;
- спуск с постоянным шагом сходится, только если `learning_rate < 2/λmax`; на нестандартизованных признаках это ограничение в тысячи раз жёстче, поэтому признаки перед обучением нужно стандартизовать.

## Ограничения

- Остановка по абсолютному изменению цели (`tol`), а не по норме градиента и не по расстоянию до решения.
- `solver="gradient"` решает L1 субградиентом, без точных нулей; точные нули даёт `solver="proximal"`, но он не поддерживает `momentum`.
- `solver="newton"` только у логистической регрессии и только с `penalty` `None` или `"l2"`; итерация стоит `O(n·d² + d³)`, поэтому на тысячах признаков он медленный.
- Веса всегда стартуют с нулей; `random_state` влияет только на перемешивание при `batch_size`.
- Расходимость распознаётся только по `J = inf` или `nan`. Потери логистической регрессии растут линейно и почти никогда не доходят до `inf`, поэтому там слишком большой `learning_rate` проявляется колебаниями и `ConvergenceWarning` по `max_iter`.
- На линейно разделимых данных без штрафа оптимума нет, веса растут до остановки по `tol` или `max_iter`.
- У `analytic` вырожденная матрица (линейно зависимые признаки) даёт решение минимальной нормы без предупреждения.
- `P(0)` считается как `1 − P(1)`, поэтому в далёком хвосте теряет точность (на классы не влияет); класс 1 присваивается при строгом `P(1) > threshold`.
- Многоклассовость только через softmax (одна модель на все классы); схем «один против всех» и многометочной классификации нет. Метки должны быть целыми.
